## Rollback

This section documents the historical slice boundary for the I14 backport; because current releases use forward-only database migrations without down-migration scripts, live deployments must follow [database recovery](../operations/incident-recovery.md#database-recovery).

Reverting the standalone provenance commit removes only the comparison manifest and documentation without affecting runtime behavior. During historical I14 development, rolling back the feature itself required stopping the scheduler and API processes, letting active node command leases settle, reverting the I14 code changes, and running down-migration `000013` only on test databases where no quota policy or batch history needed to be kept. No upstream runtime, database, container, or privileged host dependency was introduced.
