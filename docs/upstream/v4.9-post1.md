- A: no files in the exact comparison.
- B: the numeric form correction is represented at the adapter boundary. The
  upstream-facing policy fields stay in `web/src/upstream/`; node scope,
  generated API calls, integer-byte conversion, UTC normalization, operation
  behavior, and RBAC stay in `web/src/adapters/` and the control plane.
- C: v4.9 quota/expiry product semantics were manually mapped to integer bytes,
  explicit receive/transmit/combined modes, UTC periods, desired policy,
  observed usage, a leased scheduler, and typed disable operations. Upstream
  GORM models and migrations are not executed.
- D: local `occtl`, local password/config file access, Docker-mode execution,
  the file cron journal, unconstrained goroutines, and permanent expired-user
  deletion are rejected.

No upstream source file is copied verbatim. The upstream behavior and MIT code
were reviewed as reference material; the implementation is isolated and can be
reverted as one I14 change. Contract, permission, migration, generated-client,
UI, E2E, security, and license checks cover the adapted result.

## Rollback

a durable state, then revert the standalone I14 commit. Apply migration
`000013` down only when no policy or batch data must be retained. No upstream
runtime, database, container, or privileged deployment dependency is introduced.
