## Reuse decisions

- A (direct reuse): none.
- B (adapter behavior): [dashboard #183](https://github.com/mmtaee/ocserv-dashboard/pull/183) serializes `ocpasswd` updates. In ocservia, `privd` already serializes password creation, rotation, enable/disable, and group updates through a single adapter `Arc<Mutex>` that covers reading, staging, and atomic publication. Because that lock is in-process, external tools must not modify the managed `ocpasswd` file while `privd` is running.
- C (product semantics): per-item success tracking, partial failure reporting, and batch cancellation are handled by the asynchronous [user batch service](../development/user-management.md#quota-expiry-and-batches), using deterministic child idempotency keys, bounded worker claims, and persisted per-item outcomes. ocservia does not expose a dashboard backup-upload endpoint.
- D (rejected): wrapping local shell commands in GORM transactions, running synchronous restore calls with HTTP timeout exemptions, and importing legacy SQLite or password files from another product ([dashboard #182](https://github.com/mmtaee/ocserv-dashboard/pull/182)) are excluded.

## Adapter safeguards

Password and configuration publication uses unique staging files in the target directory, descriptor-relative `O_NOFOLLOW` access, ownership/mode/hardlink checks, and signed root effect records. Any in-flight staged transition is resolved before the next mutation runs, and command replay relies only on the authenticated `privd` receipt or `Agent` journal (inspecting disk files alone never synthesizes a receipt, so a crash between applying an effect and signing its receipt settles as `Unknown`).

When a child command times out or is canceled, the adapter removes `ocpasswd`'s adjacent `<staging>.tmp` file. At startup, cleanup touches only private, root-owned, single-link UUIDv7 staging files (including their `.tmp` companions) and fails closed if it encounters unsafe legacy leftovers. `privd` runs under `UMask=0077`, while [Ocpasswd 1.5.0](https://gitlab.com/openconnect/ocserv/-/blob/1.5.0/src/ocpasswd/ocpasswd.c) sets `umask(066)` and creates `0600` scratch files before root ownership normalization; the `privd` Unix socket is explicitly set to `0660`, and configuration publication restores the target file's mode. A single execution deadline covers child `stdin`, process exit, and output pipes, backed by process-group termination if grandchild processes outlive the child.

## Compatibility and validation

Adapter validation targets source-built Ocserv 1.5.0 (commit `49f9956eeeffd613e4bcac3f6450c682ec21e75a`) on Debian 12 Linux ARM64 with live `ocserv`, `occtl`, `ocpasswd`, OpenConnect, and OpenSSL binaries. Output parsers follow the tagged source and binary output where older man-page descriptions differ. The `1.2`, `1.3`, and `1.4` test fixtures cover parser regressions without certifying full package or security acceptance, and future point releases such as `1.5.1` require explicit validation before admission. Unreleased upstream path-hardening patches are not imported; ocservia enforces its own path and identifier validation at the Controller and `privd` boundaries.

Run the focused checks from an isolated checkout inside an authorized disposable Linux/TUN environment (see [testing](../development/testing.md)) without installing `ocserv` onto a shared host:

- `cargo test --locked -p ocservia-ocserv-adapter -p ocservia-privd`: verifies execution deadlines, cancellation, scratch-file cleanup, permissions, rollback, authenticated recovery, replay handling, attested CSRs, and encrypted P12 bundles.
- `scripts/i13-native-ocserv-integration.sh`: exercises live VPN authentication, password rotation, lock/group updates, `occtl` output parsing, session termination, concurrent writes, and command replay without running a host-installing Agent smoke test.
- `TestUserOperationsBackendIntegration`: verifies partial batch outcomes and durable child-task recovery without duplicating commands, outbox rows, or audit events (database integration tests do not substitute for live node execution or full backup restoration).

Record the exact run identities and outputs in the validation evidence. Simulated crash fixtures do not substitute for physical power-loss or multi-host testing. Because this increment added no database schemas, wire fields, or privileged operations, rolling back the adapter code requires stopping dispatch, reconciling in-flight commands, and restoring a matched `Agent`/`privd` pair while keeping the root effect store, HMAC/receipt keys, and local SQLite journal intact (note that reverting the parser drops `1.5.0` version recognition).
